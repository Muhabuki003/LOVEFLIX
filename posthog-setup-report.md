### distinctId conventions used

| Prefix | When | Mapping plan |
|---|---|---|
| `<uuid>` (Supabase user.id) | Default whenever the user is known | None needed |
| `customer_<cus_id>` | Stripe webhooks before a user mapping exists | Add a `customers(user_id, stripe_customer_id)` lookup in the webhook and switch to user.id once it's in place. PostHog will then merge the customer-prefixed identity into the user identity via `posthog.alias`. |
| `email_<lowercased>` | `checkout_started` from a non-authed browser | Same — alias once the resulting Stripe session resolves to a user. |
| `ip_<cf-connecting-ip>` | Anonymous landing-page AI chat | Acceptable, transient. Don't worry about merging. |

## Suggested PostHog dashboards / insights to build

1. **Couple activation funnel**  
   `user_signed_up` → `partner_invite_sent` → `partner_invite_redeemed` → `couple_paired_completed`  
   Tells you the % of solo signups who actually pair, which is the load-bearing metric for the product.

2. **Trial-to-paid conversion**  
   `paywall_seen` → `checkout_started` → `subscription_activated`  
   Trial is 14 days (`subscription_data[trial_period_days]: 14`), so funnel windows of 1d / 7d / 14d / 30d are the useful ones.

3. **Content engagement, couple-grouped**  
   `video_playback_started` and `video_playback_completed`, grouped by `couple` group (not user). Average completes per couple per week is a better retention indicator than per-user views.

4. **Music + AI co-engagement**  
   `music_track_played` and `ai_message_sent` as secondary value events — couples who hit both early tend to retain.

5. **Subscription health**  
   Cohort: users with `subscription_activated` minus users with `subscription_canceled` or `subscription_payment_failed` (last 30d).

6. **Anonymous AI funnel (landing page)**  
   `ai_message_sent` where `surface = landing` → `user_signed_up`. Tells you if the landing concierge actually drives signups.

## What was skipped and why

- **`favorite_added` event.** The router (`functions/api/[[path]].js:351`) references `addFavorite`, `listFavorites`, `removeFavorite`, but those functions aren't defined anywhere in the file. Calling `POST /api/favorites/:id` would throw `ReferenceError` *before* any analytics call. Fixing the handler is out of scope for this skill; once it's defined, the capture pattern is two lines (`await phCapture(env, { distinctId: user.id, event: 'favorite_added', properties: { video_id } })`).
- **Admin pages** (`admin*.html`). Phase 2 explicitly excluded them — internal-only, not product signal.
- **Editor SPA** (`editor/`). Pre-built Vite bundle, no source in this repo. PostHog would only see pageviews of `editor/index.html`, which the auto-pageview event already captures via the static-HTML loader. If you want richer editor events, add captures to the editor's source repo and re-export the bundle.
- **Per-tick `video_playback_progress_saved`.** Phase 2 specified milestone-gated (25/50/75/95%) captures, but that requires the video duration on every save (extra D1 hit). Simplified to one `video_playback_completed` event when `completed=1`, which is the actionable signal. If you want milestone progress later, add `duration_seconds` to the `watch_progress` table and re-enable the gating.

## Verification once the key is set

After `wrangler pages secret put POSTHOG_PROJECT_API_KEY`:

1. Hit any page (e.g. `/home.html`), open DevTools → Network, filter for `ingest`. Expect:
   - `GET /ingest/static/array.js` (or `recorder.js`) → 200
   - `POST /ingest/e/?ip=…&_=…` → 200, body contains the auto `$pageview`
2. Sign in. Check PostHog → Live events for `user_signed_in` within ~5s.
3. Trigger a test Stripe webhook (`stripe trigger checkout.session.completed`). Expect `subscription_activated` in Live events.
4. From PostHog → People → search by your Supabase user.id; confirm `email`, `created_at` traits are set, and the `couple` group association exists.
